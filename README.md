# kratos

Personal, self-hosted [shadcn](https://ui.shadcn.com) registry. Each codenamed design system lives as its own fully self-contained registry package under `packages/`, and `apps/docs` hosts the JSON endpoints plus a docs site showcasing every component live.

Not published to npm or the public shadcn directory — distribution is purely `shadcn add @kratos-<codename>/<item>` pointed at this repo's hosted registry JSON.

## Structure

- `apps/docs` — Next.js + Fumadocs docs site. Serves `/r/<codename>/<item>.json` (static files generated by `registry:build`) and renders live previews.
- `packages/<codename>` — one full design system per codename (own `button`, `input`, hooks, blocks, theme). First one: `orion`.

## Adding a new codename

1. `mkdir packages/<codename> && cd packages/<codename>`
2. `pnpm dlx shadcn@latest init` (pick style/base color/etc for this codename)
3. Author components under `registry/`, list them in `registry.json`
4. Add a `registry:build` script: `"shadcn build --output ../../apps/docs/public/r/<codename>"`
5. Add docs under `apps/docs/content/docs/<codename>/`

## Consuming a registry from another project

```jsonc
// components.json
{
  "registries": {
    "@kratos-orion": "https://<your-domain>/r/orion/{name}.json"
  }
}
```

```sh
pnpm dlx shadcn@latest add @kratos-orion/button
```

## Development

```sh
pnpm install
pnpm dev
```

`pnpm dev` builds every registry (`registry:build`) before starting the docs app, so `/r/**` is always fresh in dev.
